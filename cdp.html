Customer Data Platform — Segment & Condition Builder

Marketers could nest conditions three levels deep and still miss that the logic resolved to zero people. The interface had to make that impossible to overlook.

Outcome
Shipped · dev built from specs
Timeline
3 months · 2024
Role
UX/UI Designer

The hard part wasn't showing more data. It was turning layered logic into a workspace marketers could read, configure and trust.

without trust the tool only confirms what you want to see

A marketer could build a segment, nest AND/OR groups two or three levels deep, and still miss that the logic quietly resolved to zero people. The interface already existed. It worked. But "works" and "works confidently" are different things.

There was no budget for a rebuild — legacy schemas and backend query constraints were untouchable. The work happened inside the existing platform.

01

A workspace for layered audience logic

Visible condition groups, clear operator blocks, and an estimated-reach panel — so the user understood the segment as it was being assembled.

see the logic take shape before it locks

Showing logic clearly takes space. The interface had to stay readable before it tried to show everything.

02

Search that shows what you're choosing

A categorized auto-complete selector with metadata visible in each result row — so users could verify a condition before adding it to the segment.

A richer selector is heavier to specify and build. Every empty state, loading state, and overflow case needed explicit rules.

03

Specs that answer the questions devs actually ask

Dynamic inputs changed behavior based on selected conditions. I mapped button states, focus rings, validation alerts, and input adapters per data variable — so the team could implement and QA against documented behaviour, not guesswork.

every undocumented edge case becomes a QA ticket

More upfront design work before any code gets written. But fewer conversations that start with "what should this do when..."

What I'd do differently

The riskiest moment in this tool is invisible — a campaign that goes out to nobody.

I'd add a validation layer that warns when condition logic resolves to zero before anything ships. I'd also instrument actual nesting depth — I designed for 2–3 levels without knowing if that matched how marketers actually worked.
